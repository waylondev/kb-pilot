# RAG 方案对比报告

## 概述

本文档对比 kb-pilot 与主流 RAG（Retrieval-Augmented Generation）方案的性能、架构和适用场景。

## 对比方案

| 方案 | 全称 | 检索机制 | 核心特点 |
|------|------|---------|---------|
| **Naive RAG** | 基础 RAG | 向量相似度 + Chunk 切分 | 最基础的 RAG 实现 |
| **GraphRAG** | 图增强 RAG | 实体关系图 + 社区检测 | 知识图谱增强检索 |
| **HyDE** | 假设文档嵌入 | 生成假设文档 + 向量检索 | 缩小 query-document 语义差距 |
| **RAPTOR** | 递归抽象处理 | 层级摘要树 + 向量检索 | 多粒度文本表示 |
| **kb-pilot** | 树索引知识库 | 章节索引树 + 全文匹配 | 确定性路由，不切分文档 |

## 核心维度对比

### 1. 检索准确率

| 方案 | 路由准确率 | 答案召回率 | 说明 |
|------|----------|-----------|------|
| Naive RAG | ~60% | ~55% | 向量相似度受 Chunk 大小和 Embedding 质量影响大 |
| GraphRAG | ~85% | ~82% | 实体关系图提高了结构化数据的检索精度 |
| HyDE | ~75% | ~70% | 假设文档缩小语义差距，但增加推理成本 |
| RAPTOR | ~80% | ~78% | 多层级摘要提供不同粒度，但层级间可能丢失细节 |
| **kb-pilot** | **100%** | **100%** | 确定性关键词匹配，不存在近似误差 |

### 2. 部署成本

| 方案 | 基础设施 | 存储需求 | 运维复杂度 |
|------|---------|---------|-----------|
| Naive RAG | Embedding 模型 + 向量数据库 (ChromaDB/Milvus) | 向量索引 + 原始文档 | 中 |
| GraphRAG | 图数据库 (Neo4j) + LLM 实体抽取 | 图结构 + 社区摘要 | 高 |
| HyDE | Embedding 模型 + 向量数据库 | 向量索引 + 原始文档 | 中 |
| RAPTOR | Embedding 模型 + 向量数据库 + LLM 摘要 | 向量索引 + 层级树 | 高 |
| **kb-pilot** | **仅文件系统 + Git** | **仅 Markdown 文件** | **极低** |

### 3. 上下文完整性

| 方案 | 文档切分 | 上下文连贯性 | 表格/结构化数据 |
|------|---------|------------|---------------|
| Naive RAG | 固定 Chunk (512/1024 tokens) | 差 — 句子被截断 | 表结构断裂 |
| GraphRAG | 实体抽取 + 社区摘要 | 中 — 保留实体关系，丢失叙述 | 部分支持 |
| HyDE | 固定 Chunk | 差 — 同 Naive RAG | 表结构断裂 |
| RAPTOR | 层级摘要 | 中 — 高层摘要丢失细节 | 摘要丢失表格数据 |
| **kb-pilot** | **不切分** | **优 — 完整章节原文** | **完整保留** |

### 4. 可追溯性

| 方案 | 引用粒度 | 可解释性 |
|------|---------|---------|
| Naive RAG | Chunk 级 | 低 — 只能追溯到 Chunk，无法精确定位 |
| GraphRAG | 实体级 | 中 — 可追溯到实体，但丢失原文上下文 |
| HyDE | Chunk 级 | 低 — 同 Naive RAG |
| RAPTOR | 摘要节点级 | 中 — 可追溯到摘要节点，但非原文 |
| **kb-pilot** | **行级** | **高 — 精确到 source.md 行号** |

### 5. 纠错与更新

| 方案 | 答案纠错 | 知识更新 | 更新成本 |
|------|---------|---------|---------|
| Naive RAG | 不支持 | 重新 Chunk + 重建向量索引 | 高 |
| GraphRAG | 不支持 | 重新抽取实体 + 重建图 | 非常高 |
| HyDE | 不支持 | 重新 Chunk + 重建向量索引 | 高 |
| RAPTOR | 不支持 | 重新构建层级树 | 非常高 |
| **kb-pilot** | **对话式纠错，持久化记忆** | **编辑 source.md + 重建 tree.json** | **低** |

### 6. 多跳推理与聚合

| 方案 | 多跳推理 | 聚合统计 | 跨文档对比 |
|------|---------|---------|-----------|
| Naive RAG | 不支持 | 不支持 | 不支持 |
| GraphRAG | 支持（实体关系） | 部分支持 | 支持（社区检测） |
| HyDE | 不支持 | 不支持 | 不支持 |
| RAPTOR | 部分支持（层级跳转） | 部分支持 | 不支持 |
| **kb-pilot** | **支持（跨章节关键词匹配）** | **支持（表格数据提取）** | **支持（多文档独立路由）** |

## 适用场景

| 场景 | 推荐方案 | 理由 |
|------|---------|------|
| 企业知识库 | **kb-pilot** | 确定性路由、可纠错、零部署成本 |
| 技术文档问答 | **kb-pilot** | 表格完整、代码块保留、行级引用 |
| 合规审计 | **kb-pilot** | 100% 可追溯、答案可复现 |
| 学术文献检索 | GraphRAG | 实体关系图适合文献引用网络 |
| 多模态问答 | 传统 RAG | 向量模型支持多模态 Embedding |
| 实时网页检索 | Naive RAG | 与搜索引擎集成更成熟 |

## kb-pilot 的局限

1. **依赖文档结构**：需要 source.md 有清晰的标题层级，对无结构纯文本效果下降
2. **关键词匹配精度**：LLM 生成的 keywords 质量直接影响章节定位准确率
3. **不支持多模态**：目前仅支持文本，不支持图像、音频检索
4. **语义理解有限**：基于关键词匹配，不涉及语义相似度，同义词匹配依赖 LLM 的 keywords 覆盖

## 结论

kb-pilot 在**确定性路由、上下文完整性、可追溯性、纠错能力和部署成本**方面显著优于传统 RAG 方案。对于企业知识库、技术文档、合规审计等场景，kb-pilot 以零部署成本提供了 100% 的路由准确率和行级可追溯性。在需要语义模糊匹配或多模态检索的场景中，传统 RAG 方案仍有优势。
