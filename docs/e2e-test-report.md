## 七、结论

### 7.1 核心发现

1. **准确性不随规模下降**：从 10 篇到 210 篇（21 倍增长），kb-pilot 的基础问答准确率保持 100%，证明了 tree.json + manifest.json 双索引架构的确定性路由优势。

2. **模糊匹配正确可用**：3 个模糊问题测试中，manifest.json 的 Top 2 候选机制成功返回了最相关的文档，涉及同领域多文档（测试 12）和跨领域关联（测试 13）两种场景，验证了 title → summary → tags 三级匹配策略的有效性。

3. **跨文档对比架构清晰**：3 个跨文档对比测试中，每个文档独立执行完整的 6 步流程，互不干扰。对比分析从多个维度展开，每个维度的依据均来自对应文档的精确行号，不存在信息混淆。

4. **conflicted 纠错机制有效**：新增 4 个文档的纠错记录（共计 14 条，6 条 conflicted），覆盖了 active 优先、conflicted 多版本展示、active+conflicted 共存标注三种场景，验证了 jsonl 纠错格式在冲突场景下的正确行为。

5. **路由效率恒定**：无论文档数量如何增长，领域路由和文档路由都是 O(1) 级别的关键词匹配，不受文档总量影响。

6. **零部署成本优势**：纯 JSON + Markdown 的架构无需任何向量数据库或 embedding 模型，对比传统 RAG 方案具有显著的部署和维护成本优势。

### 7.2 局限性

- 当前 16 个测试用例覆盖了 14 个领域，仍有 37 个领域未测试
- 纠错记录的 conflicted 场景均基于已构造的测试数据，尚未在真实用户协作中验证
- 所有文档均为自动生成的结构化 Markdown，真实世界的非结构化文档可能需要更多测试

### 7.3 建议

- 继续增加文档至 500+ 篇，验证 manifest.json 在更大规模下的路由性能
- 在真实多人协作场景中测试 conflicted 纠错的完整流程
- 引入非结构化文档（如会议纪要、技术博客）验证 tree.json 构建的鲁棒性
