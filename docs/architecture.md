# 系统架构

## 整体架构

kb-pilot 采用 **文件系统 + 树索引** 架构，完全不同于传统 RAG 的向量检索 + 文档切分模式。

```
┌─────────────────────────────────────────────────────────┐
│                      Agent (LLM)                         │
│                                                         │
│  ┌──────────────┐              ┌──────────────────────┐ │
│  │  kb-ingest    │              │      kb-chat         │ │
│  │  (文档接入)    │              │     (知识问答)        │ │
│  └──────┬───────┘              └──────────┬───────────┘ │
│         │                                 │              │
└─────────┼─────────────────────────────────┼──────────────┘
          │                                 │
          ▼                                 ▼
┌─────────────────────────────────────────────────────────┐
│                    知识库 (文件系统)                       │
│                                                         │
│  ┌──────────────┐  ┌──────────────┐  ┌───────────────┐ │
│  │ manifest.json │  │  tree.json   │  │  source.md    │ │
│  │ (全局路由表)   │  │ (章节索引树)  │  │  (原始文档)    │ │
│  └──────────────┘  └──────────────┘  └───────────────┘ │
│                                                         │
│  ┌──────────────┐  ┌──────────────────────────────────┐ │
│  │ metadata.yaml │  │  memory/                         │ │
│  │ (元数据)       │  │  (纠错记录 + 路由偏好)             │ │
│  └──────────────┘  └──────────────────────────────────┘ │
└─────────────────────────────────────────────────────────┘
```

## 核心组件

### 1. 全局路由表（manifest.json）

`docs/` 目录下所有文档的索引，由 `build_manifest.py` 自动生成。

每个条目包含：
- `doc_id`：文档唯一标识
- `title`：文档标题
- `domain`：所属领域
- `summary`：文档摘要（从 tree.json 拼接）
- `tags`：关键词集合（从 tree.json 所有节点收集）
- `path`：文档相对路径

### 2. 章节索引树（tree.json）

单篇文档的章节结构树，由 `build_tree.py` 生成骨架，LLM 填充语义信息。

每个节点包含：
- `id`：节点唯一标识
- `level`：标题层级（2=##, 3=###）
- `title`：章节标题
- `anchor`：Markdown 锚点（用于精确定位）
- `summary`：章节摘要（≤20 字，LLM 生成）
- `keywords`：关键词列表（3-8 个，LLM 生成）
- `start_line` / `end_line`：原文行号范围
- `children`：子节点列表

### 3. 原始文档（source.md）

Markdown 格式的完整文档，不切分，保留所有原始内容和结构。

### 4. 元数据（metadata.yaml）

文档的元信息，包括 doc_id、标题、领域、维护人、转换质量等。

### 5. 记忆系统（memory/）

记忆系统让知识库具备"学习"能力，支持答案纠错和路由偏好记忆。

#### 5.1 纠错记录（corrections/）

当知识库原文存在过时或错误信息时，用户可以通过对话纠正，系统将纠正内容持久化。

**存储格式**：`memory/corrections/{doc_id}.jsonl`，每行一条 JSON 记录：

```jsonl
{"timestamp":"2026-08-01T10:00:00+08:00","question":"DeepSeek V3 参数量","correct_answer":"671B (MoE)，激活37B","doc_id":"doc_001","source_ref":"用户纠正","status":"active"}
```

**纠错状态**：

| 状态 | 含义 | 处理方式 |
|------|------|---------|
| `active` | 生效中的纠错 | 优先使用纠错后的答案 |
| `conflicted` | 存在冲突的纠错 | 展示所有版本，让用户选择 |

**纠错流程**：

```
用户指出错误
    │
    ▼
检查 memory/corrections/{doc_id}.jsonl
    │
    ├── 无相似记录 → 追加 active，用新答案回答
    ├── 有记录且答案相同 → 跳过（已存在）
    └── 有记录且答案不同 → 追加 conflicted，展示所有版本
```

**纠错加载**（kb-chat Step 5）：每次问答时，自动读取对应文档的纠错记录，附加到 LLM 上下文中。LLM 自行判断是否有相关纠错：
- 有 `active` 纠错 → 优先使用
- 有 `conflicted` 纠错 → 展示所有版本让用户选择
- 无纠错 → 直接使用原文

#### 5.2 路由偏好（route_preferences.json）

记录用户明确表达的领域偏好，后续问答自动优先检索指定领域。

**存储格式**：

```json
{
  "domain_preferences": ["01_金融", "03_技术"],
  "updated_at": "2026-08-01T10:00:00+08:00"
}
```

**触发方式**：用户说"我以后主要问股票"、"我主要关注技术领域"等。

**生效方式**：kb-chat Step 1 领域路由时，优先读取 `route_preferences.json`，结合问题关键词判断目标领域。偏好领域在匹配时给予更高权重。

**重要约束**：仅存储用户**明确表达**的偏好，不从对话历史中推断。

## 数据流

### 文档入库流程

```
原始文档 (PDF/Word/HTML)
    │
    ▼
source.md (Markdown 转换)
    │
    ├──► metadata.yaml (LLM 创建元数据)
    │
    ├──► build_tree.py ──► tree.json 骨架
    │         │
    │         ▼
    │    LLM 填充 summary + keywords
    │
    └──► build_manifest.py ──► manifest.json
```

### 问答流程

```
用户问题
    │
    ▼
1. 领域路由 ──► route_preferences.json
    │
    ▼
2. 文档路由 ──► manifest.json (title → summary → tags 匹配)
    │
    ▼
3. 章节定位 ──► tree.json (keywords 匹配)
    │
    ▼
4. 内容截取 ──► source.md (start_line → end_line)
    │
    ▼
5. 纠错加载 ──► memory/corrections/
    │
    ▼
6. 生成答案 ──► 答案 + 依据 + 置信度
```

## 设计原则

1. **确定性优先**：所有路由和定位逻辑可复现，不依赖概率模型
2. **LLM 增强语义**：仅用 LLM 填充 summary 和 keywords，检索本身是确定性的
3. **文件即数据库**：文件系统即存储层，Git 即版本控制
4. **最小依赖**：仅需 Python 标准库 + PyYAML，无外部服务依赖
