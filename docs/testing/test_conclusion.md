# kb-pilot 测试报告结论（2026-08-31）

**一句话结论**：在预置条件内（结构良好、高质量文档、单文档答案成立、规模适中），kb-pilot 三个 skill 稳定且准确率高。kb-chat 累计 **1042 条 QA**（907 条 E2E 盲测，严格正确率 99.1%；135 条针对性深入测试，100%）中**未发现 skill 逻辑缺陷**。

## 执行方式与判定标准（先读这段再读结论）

| 测试批次       | 条数  | 执行方式                                                           | 判定方式                        |
| ---------- | --- | -------------------------------------------------------------- | --------------------------- |
| E2E 盲测     | 907 | kb-chat **真实运行**（RAG-Multi-Corpus benchmark，统一库 236 篇/5 域）     | 对照**独立参考材料**，strict 匹配      |
| 深入测试 1-6 轮 | 135 | **人工模拟 skill 五步流程**（按约定不运行脚本；结构/语义由人读 manifest、tree.json、源文完成） | **自出题、自答、自判**，每条带行级引用并对源文核验 |

**判定标准（strict）**：数字/枚举完全匹配、abstention（未提及）正确、引用行号有效且内容与源文吻合；凡源文无法支持则答"未提及"，不编造。

**偏差披露**：深入测试为作者自测，出题人即判卷人，存在**测试者偏差**；行级引用对源文逐一核验可部分抵消该偏差，但**不等同于独立盲测**。因此"135/135"是"在自设用例与自定标准下未发现问题"，不构成与 E2E 同等的客观性。

## 拐点结论（核心）

**kb-pilot 唯一的系统固有拐点是 manifest 规模，与文档质量无关。**

| 维度     | 状态          | 依据与口径                                                                                                                                                                                |
| ------ | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 成本拐点   | **已到**      | 615 篇/22 域 manifest 实测 313,996 字节 / 232,472 字符；**估算**约 8.2 万 token（折算口径：中文 40,382 字符按 \~1.2 字/token ≈ 3.4 万、非中文 192,090 字符按 \~4 字符/token ≈ 4.8 万；未用真实 tokenizer 复核）。每题路由全量读取，随文档线性膨胀 |
| 正确性拐点  | **未到**      | 在**已测**的最大候选集（91）下语义排名零串扰，135/135 深入测试通过；**未对 1000+ 篇实测**，此为已测范围内的观察而非普遍断言                                                                                                           |
| 硬性可行拐点 | **可预见（外推）** | 按每篇约 133 token 的当前平均 manifest 规模线性外推：128K 窗口约 900\~1,000 篇、200K 窗口约 1,500 篇时路由读不完 manifest，正确率断崖下降。**假设**：单篇摘要/元数据规模不变、窗口按 128K/200K 计                                               |

**处置**：控规模——超几百篇拆仓（one repo = one cognitive boundary）或精简 manifest，而非加检索结构。

**填充质量与同主题密度是输入前提（文档/语料质量），不是 kb-pilot 的问题**；kb-pilot 对其耐受度反而高于向量 RAG——它全量读、失败可见可诊断（如空 tags 一目了然）、冲突会被呈现，而向量系统是静默失效。

## 覆盖与局限（诚实声明）

1. **深入测试用例分布**：1-4 轮集中在 2 个小众域+既有语料抽查；第 5-6 轮扩展到拐点压力与 11 个新域（共覆盖 17 个域/21 篇目标文档），但**仍未对全部 615 篇逐一深入测试**；E2E 907 条是唯一覆盖全库（236 篇基准）的批次。
2. **审计链不完整**：逐题记录第 5 轮（`kb-chat_inflection_round_qa.md`）与第 6 轮（`kb-chat_multi_scene_round_qa.md`）完整落盘；第 1-4 轮逐题记录未持久化（`kb-chat_niche_round_qa.md` 已丢失、`kb-chat_deep_test_37.md` 未落盘）——本文档的维度表与判定是这些用例的**唯一留存**，无法逐条复审。
3. **估算与外推未实测**：token 消耗为折算估算；1000+ 篇硬拐点为线性外推，二者均未在真实窗口/tokenizer 下验证。
4. **预置条件边界**：全部结论仅在"结构良好、高质量文档、单文档答案成立、规模适中"内成立；超出即超出测试范围。

## 三技能表现

* **kb-chat**：路由准（文档越多语义路由优势越明显）、abstention 可靠、引用可追溯。

* **kb-ingest**：结构层（标题/行号/SHA256/doc\_id）100% 正确；LLM 填充质量决定后续路由质量。

* **kb-polish**：辅助 skill，把异构文档转成可入库 Markdown，人工确认兜底。

## 复现方法

1. kb-ingest 正确结束（0 空节点、0 drift、manifest 完整）。
2. kb-chat 按五步流程作答：路由（读 manifest → 语义候选）→ 定位（读 tree.json → 语义选节）→ 提取（查 drift → 读源文）→ 生成（行级引用）→ 自验证（逐位核对）。
3. 每条对照源文核对引用行号与内容吻合度；按上文判定标准计 strict 正确率。
