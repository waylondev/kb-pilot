# 系统架构

## 整体架构

kb-pilot 采用 **文件系统 + 树索引** 架构，完全不同于传统 RAG 的向量检索 + 文档切分模式。

```
┌─────────────────────────────────────────────────────────┐
│                      Agent (LLM)                         │
│                                                         │
│  ┌──────────────┐              ┌──────────────────────┐ │
│  │  kb-ingest    │              │      kb-chat         │ │
│  │  (文档接入)    │              │     (知识问答)        │ │
│  └──────┬───────┘              └──────────┬───────────┘ │
│         │                                 │              │
└─────────┼─────────────────────────────────┼──────────────┘
          │                                 │
          ▼                                 ▼
┌─────────────────────────────────────────────────────────┐
│                    知识库 (文件系统)                       │
│                                                         │
│  ┌──────────────┐  ┌──────────────┐  ┌───────────────┐ │
│  │ manifest.json │  │  tree.json   │  │  source.md    │ │
│  │ (全局路由表)   │  │ (章节索引树)  │  │  (原始文档)    │ │
│  └──────────────┘  └──────────────┘  └───────────────┘ │
│                                                         │
│  ┌──────────────┐  ┌──────────────────────────────────┐ │
│  │ metadata.yaml │  │  memory/                         │ │
│  │ (元数据)       │  │  (纠错记录 + 路由偏好)             │ │
│  └──────────────┘  └──────────────────────────────────┘ │
└─────────────────────────────────────────────────────────┘
```

## 核心组件

### 1. 全局路由表（manifest.json）

`docs/` 目录下所有文档的索引，由 `build_manifest.py` 自动生成。

每个条目包含：
- `doc_id`：文档唯一标识
- `title`：文档标题
- `domain`：所属领域
- `summary`：文档摘要（从 tree.json 拼接）
- `tags`：关键词集合（从 tree.json 所有节点收集）
- `path`：文档相对路径

### 2. 章节索引树（tree.json）

单篇文档的章节结构树，由 `build_tree.py` 生成骨架，LLM 填充语义信息。

每个节点包含：
- `id`：节点唯一标识
- `level`：标题层级（2=##, 3=###）
- `title`：章节标题
- `anchor`：Markdown 锚点（用于精确定位）
- `summary`：章节摘要（≤20 字，LLM 生成）
- `keywords`：关键词列表（3-8 个，LLM 生成）
- `start_line` / `end_line`：原文行号范围
- `children`：子节点列表

### 3. 原始文档（source.md）

Markdown 格式的完整文档，不切分，保留所有原始内容和结构。

### 4. 元数据（metadata.yaml）

文档的元信息，包括 doc_id、标题、领域、维护人、转换质量等。

### 5. 记忆系统（memory/）

- `corrections/`：纠错记录，JSONL 格式，支持 active/conflicted 状态
- `route_preferences.json`：用户路由偏好

## 数据流

### 文档入库流程

```
原始文档 (PDF/Word/HTML)
    │
    ▼
source.md (Markdown 转换)
    │
    ├──► metadata.yaml (LLM 创建元数据)
    │
    ├──► build_tree.py ──► tree.json 骨架
    │         │
    │         ▼
    │    LLM 填充 summary + keywords
    │
    └──► build_manifest.py ──► manifest.json
```

### 问答流程

```
用户问题
    │
    ▼
1. 领域路由 ──► route_preferences.json
    │
    ▼
2. 文档路由 ──► manifest.json (title → summary → tags 匹配)
    │
    ▼
3. 章节定位 ──► tree.json (keywords 匹配)
    │
    ▼
4. 内容截取 ──► source.md (start_line → end_line)
    │
    ▼
5. 纠错加载 ──► memory/corrections/
    │
    ▼
6. 生成答案 ──► 答案 + 依据 + 置信度
```

## 设计原则

1. **确定性优先**：所有路由和定位逻辑可复现，不依赖概率模型
2. **LLM 增强语义**：仅用 LLM 填充 summary 和 keywords，检索本身是确定性的
3. **文件即数据库**：文件系统即存储层，Git 即版本控制
4. **最小依赖**：仅需 Python 标准库 + PyYAML，无外部服务依赖
